Rule and test design

Per the README and OpenAPI checkout contract, cash receives a 10% discount, credit card receives no discount, and unsupported payment methods are rejected. Equivalence partitioning was used as the sole test design technique.

Each accepted payment method is its own partition because it produces a different discount result. Unsupported payment-method strings form the rejection partition. A representative was selected for each partition; the unsupported string and seeded product for each case were selected randomly. The allowed payment partitions each contain one value.
